# ADR-022: Private bank synchronization and receipt reconciliation

Status: Accepted. Implements the seam in ADR-005 and extends ADR-007/008 storage.

## Decision

Use Enable Banking's official account-information API (AIS) for personal mBank in Poland. No bank passwords, UI scraping, notification interception or payment initiation. Select mBank from the authenticated provider directory; browser authorization returns to the registered root URL. Consume a hashed, owner-bound, ten-minute state once before exchanging the code. Require a current owner session for both ends of authorization.

Keep this private pilot disabled by default. One authenticated application administrator who owns the chosen household activates it after password reauthentication, typing the household name and explicitly sharing account information with its exactly two current members. Persist that household UUID, owner UUID and the two approved user UUIDs outside source control; names/email guesses cannot grant access. Membership is checked on every request. Additional members and other households cannot access the bank feed, management or bank-specific export. Ordinary household transaction data continues to follow existing shared-budget permissions. Changing the private binding requires trusted server administration. Do not hard-code the customer's identity or credentials into distributable images.

The provider RSA key, separate Fernet encryption key, VAPID signing key and binding configuration form a small server-side file secret store in the existing private persistent receipt volume (`.bank/`, mode 0700; files 0600). This intentionally extends the environment-only default in AGENTS.md for the existing self-hosted storage model: activation must be possible from the owner's phone without SSH, new mounts or secrets in CI. No public file route serves this folder. Encrypt provider sessions/account UIDs and device subscriptions in PostgreSQL; store hashed stable account identity/reference/counterparty identifiers and only the last four account digits. Keep secrets out of response bodies, validation errors, logs, exports, browser storage, MCP and image build contexts. Private server backups now also contain these secret files and must be protected accordingly.

BankConnection/BankAccount/BankEntry are provider boundary records. Stable account identification preserves mappings when session/account UIDs change. A bank account maps once to a PLN Account plus an explicit history start date. A server thread runs only in production; durable connection leases allow fetching at most once per six hours, including manual refresh and process restarts. Provider calls hold no household financial locks. Validate every page and account before an atomic batch; serialize writes under the household lock, recheck ownership/connection, deduplicate booked `entry_reference` per account and retain previous results on errors. Pending authorizations are never booked. Unsupported currencies are not imported into the PLN ledger.

Store the complete first import (including today), credits/history/uncertain identifiers as reviewable bank entries. Automatically book only new reliable debits without a plausible existing transaction or known own-account counterparty; use the existing integer-grosze domain and unallocated review tasks. Explicitly match equal-value/date/account candidates. Own transfers may link both bank legs to one existing transfer, without income/spending inflation. Credits require a user to classify income versus own transfer/refund; do not guess that every credit is new income. Balance comparison shows bank booked balance, application balance and the unexplained difference; never silently rewrite opening balances or clear differences.

A receipt can enrich an existing bank-linked expense after amount/account/date and revision checks, replacing allocations atomically without a second financial movement. A plausible bank payment blocks separate receipt booking until the user explicitly confirms a separate purchase. Receipt-first bank matching uses the same shared Transaction. Bank-linked amount/account/date cannot be edited as though they were an ordinary manual movement; attaching a receipt preserves documentary/category invariants.

Web Push is an explicit per-device opt-in for the two approved current members. Encrypt subscriptions, restrict delivery hosts to the supported browser push services, and maintain a transactional outbox with retries, expiry cleanup and no historical-import notification flood. Send generic messages without amounts/recipients. iPhone requires an installed Home Screen PWA on iOS 16.4+; Android requires a compatible browser and notification permission. Push failure never loses the in-app bank entry. Bank consent/subscription endpoints are excluded from the MCP catalog.

Disconnection stops fetching immediately and retries remote consent revocation if necessary. Keep imported records for reconciliation. Household deletion requires completed revocation, deletes bank data in dependency order and removes its private keys/configuration. Migration 015 adds tables only, permits the previous API image on the new schema, and refuses a downgrade that would discard bank history.

## Consequences and limits

No new production service, host mount or CI-held bank credential is required. Authorization and device opt-in remain actions in the owner's authenticated browser after deployment. Restricted production application metadata can be checked without reading real transactions; this does not prove live bank consent, statement consistency or phone delivery. Enable Banking currently labels personal mBank beta. Contract/pricing and actual bank availability remain the operator's responsibility; no real-time or free-service promise is made.
